# Branchdesk

[English](README.md) · [한국어](README.ko.md) · **日本語**

**Windows と WSL2 の Git プロジェクトを、1 つのアプリで管理できます。** 変更の確認、コミット、ブランチ切り替え、pull・push を画面から操作できます。日本語・英語・韓国語に対応しています。

初めて使う方は、[起動](#1-アプリを起動する) → [プロジェクトを開く](#2-作業するプロジェクトを開く) → [コミットと push](#3-ファイルを編集してコミットpush-する) の順に進めてください。細かい設定やソースからのビルドは[詳細リファレンス](docs/reference.ja.md)にまとめています。

## 1. アプリを起動する

1. [Branchdesk.exe をダウンロード](https://github.com/antam2010/branchdesk/raw/refs/heads/main/Branchdesk.exe)し、好きなフォルダーに保存します。このリポジトリをクローン済みなら、その中の `Branchdesk.exe` を使ってください。
2. Windows 11 x64 で `Branchdesk.exe` をダブルクリックします。
3. 初期設定が表示されたら Git・Python を接続します。Windows 単独でも、既存の WSL 環境でも使えます。
4. 右上の言語選択で **日本語** を選びます。次回の起動でも設定を記憶します。

Git 2.28 以上と Python 3.9 以上が必要です。インストール済みの実行ファイルを接続するか、未導入なら初期設定の **アプリ専用フォルダーにインストール** を使ってください。画面表示には Windows の Microsoft Edge を使います。EXE で利用する場合、ソースのビルドや Python パッケージのインストールは不要です。

## 2. 作業するプロジェクトを開く

ここで開くのは、**開発するプロジェクトの Git リポジトリ**です。Branchdesk 自体を置いたフォルダーとは区別してください。

### PC にプロジェクトがある場合

1. **リポジトリを開く → 既存のリポジトリを開く** を選びます。
2. このリポジトリで使う環境を選び、プロジェクトのフォルダーパスを入力します。
3. 確定すると、タブとコミット履歴が開きます。

実行環境は、**このプロジェクトの Git をどこで動かすか**を決める設定です。

| プロジェクトの場所 | 選ぶ環境 | パスの例 |
| --- | --- | --- |
| Windows のフォルダー | Windows | `C:\projects\my-app` |
| Ubuntu など WSL 内の Linux フォルダー | 対応する WSL2 ディストリビューション | `/home/user/projects/my-app` または `~/projects/my-app` |

必要な環境がなければ **＋ 実行環境を追加** で Windows または WSL2 を選び、**この環境に接続** を押してください。Git・Python を自動検索します。見つからない場合や特定のバージョンを使う場合だけ、**実行ファイルのパスを指定（任意）** を開いて入力します。

Windows と WSL のプロジェクトを、別々のタブで同時に開けます。WSL のプロジェクトには対応する WSL 環境と `/home/...` のパスを指定すると、その環境の Git がファイルを処理します。

### GitHub・GitLab にだけプロジェクトがある場合

1. サービスの画面で Git のクローン URL をコピーします（例：`https://github.com/your-account/my-app.git`）。
2. **リポジトリを開く → リモートリポジトリをクローン** を選びます。
3. URL、実行環境、**新しく作るローカルフォルダーのパス**を入力し、実行します。

クローンはプロジェクトを初めて PC に取得する操作です。取得済みなら **既存のリポジトリを開く** を使ってください。新規プロジェクトを始める場合は **空のリポジトリを作成** を選べます。

## 3. ファイルを編集してコミット・push する

例えば、`feature/login` ブランチでログイン画面を修正したら、次の順序で保存します。

1. VS Code や IntelliJ などのエディターでファイルを編集して保存します。
2. Branchdesk で **更新** を押し、左の **ファイルの状態** を開きます。
3. 変更ファイルをクリックし、差分を確認します。新規テキストファイルは全文を表示します。
4. 今回のコミットに含めるファイルの **＋** を押してステージします。選び直す場合は **−** で解除します。
5. `ログインフォームの入力検証を追加` などのメッセージを入力し、**コミット** を押します。
6. 共有するには **push** を選び、リモート（通常は `origin`）と送信先のブランチを確認して実行します。

**コミットは PC 内に作業履歴を保存し、push はそのコミットを GitHub・GitLab などに送ります。** ステージは今回保存する変更を選ぶ段階です。他の変更は次のコミット用に残ります。

コードレビューを依頼するには **リモート** でリポジトリの Web ページを開き、Git サービス上で PR/MR を作成してください。

コミットボタンが無効なら、ステージした変更とメッセージがあるか確認してください。名前・メールのエラーは[困ったとき](#困ったとき)を参照してください。

## 4. チームの最新変更を取得する

作業前に現在のブランチを確認し、**pull** で最新の変更を取り込みます。未完了の変更がある場合は、先にコミットするか **stash** に一時保存してください。

| ボタン | 動作 | 使う場面 |
| --- | --- | --- |
| fetch | リモートの最新コミット・ブランチ情報を取得します。作業ファイルは変更しません。 | チームの変更を先に確認する |
| pull | リモートの変更を現在のローカルブランチに取り込みます。 | プロジェクトを最新にする |
| push | ローカルのコミットを選択したリモートブランチへ送ります。 | 完了した作業を共有する |
| リモート | 接続先リポジトリの Web ページを開きます。 | GitHub・GitLab で PR/MR などを見る |
| リモート設定 | 接続 URL の確認・追加・変更を行います。 | `origin` などの接続を管理する |

pull の既定は **Fast-forward のみ**です。双方の履歴が分岐していない場合に進みます。拒否されても作業が削除されるわけではありません。merge・rebase が必要な場合は、チームの運用に合わせて選んでください。

## 5. ブランチの確認・切り替え・作成

左のブランチ一覧では、**シングルクリックでグラフ上のコミット位置を表示し、ダブルクリックで切り替えの確認画面を開きます。** 1 回クリックしただけでは作業ブランチは変わりません。

切り替え先の名前を確認して確定してください。**クリーンアップ（変更・ステージ・新規ファイルを破棄）** は既定でオフです。オンにすると表示された未コミットの変更を破棄するため、作業を残す場合はオフのまま使ってください。

新しい作業には **ブランチ → ブランチを作成** を使い、`feature/login` などの名前と開始点を指定します。**作成後にチェックアウト** を選ぶと、新しいブランチへすぐ移動します。リモートにだけあるブランチは **リモートブランチを追跡** でローカルの作業ブランチを作れます。

マージ、競合解決、コミットの取り消し、タグ、Git Flow は[機能の詳細](docs/reference.ja.md#主な操作)を参照してください。

## 6. ホームと保存済みプロジェクトを使う

- 左上の **ホーム** に、最近開いたプロジェクトの名前とパスを表示します。クリックして開き直すか、既存のタブに戻れます。
- ホームに移動しても、開いているタブと入力途中のコミットメッセージは維持します。
- タブの **×** はタブだけを閉じます。最近使ったリポジトリから開き直せます。
- **一覧から削除** はタブと履歴だけを削除し、実際のプロジェクトフォルダーは削除しません。移動・削除済みのパスも整理できます。

**履歴** でコミットをクリックすると変更を確認できます。ファイルのダブルクリックでプレビューを拡大できます。コミット・ファイル・ブランチ・タブを右クリックすると、その項目のメニューが開きます。現在のプロジェクトフォルダーを開くには **ターミナル・エクスプローラー** を使ってください。

## 7. アプリを更新する

右上の **アプリ更新 → 新しいバージョンを取得 → 適用して再起動** を使います。ダウンロード中は作業を続けられ、適用時にアプリが再起動します。開いていたリポジトリと入力途中のコミットメッセージを復元します。

**アプリ更新とプロジェクトの pull は別の操作です。** アプリ更新は実行用の Branchdesk を更新します。開発中のプロジェクトで `git pull` は実行しません。Branchdesk のソースと README も、作業フォルダーで別途 `git pull` すると更新されます。

## 困ったとき

| 状況 | 確認すること |
| --- | --- |
| Git・Python が見つからない | **実行環境** で対象を確認します。自動検索できなければパスを指定するか、**必要なプログラムをインストール** を使ってください。 |
| クローン・fetch・pull・push の認証に失敗する | プロジェクトに選んだ Windows/WSL 環境の認証を使います。SSH は下記、HTTPS は利用する Git サービスの認証設定を確認してください。 |
| コミットで名前・メールを求められる | 対象プロジェクトの **ターミナル** で、下記の Git ユーザー情報を設定します。 |
| pull が拒否される・競合する | ローカル変更をコミット・stash して確認します。双方に別のコミットがあれば、チームの運用に従って merge・rebase が必要です。競合解決は詳細文書を参照してください。 |
| pull・push・リモートが無効になる | **リモート設定** で接続 URL を確認してください。空のリポジトリは最初のコミットを作成してから共有します。 |
| 削除したプロジェクトを開けない | エラー画面や最近使ったリポジトリの **一覧から削除** で整理できます。 |
| ターミナル・エクスプローラーが前面に出ない | アプリの結果メッセージと Windows のタスクバーで開いたウィンドウを確認してください。 |
| アプリ更新で `Replace`・パス形式のエラーが出る | 古い更新ヘルパーの不具合です。アプリを閉じ、**Branchdesk のリポジトリフォルダーで** `git pull` して、その中の新しい `Branchdesk.exe` を一度起動してください。 |
| README などのローカル変更で `git pull` が中止される | 編集をコミットまたは stash に保存してから pull してください。編集の削除や強制リセットは不要です。 |

**現在のプロジェクトだけに**ユーザー情報を設定する例です。名前とメールを自分の情報に置き換え、そのプロジェクトのターミナルで実行してください。

```bash
git config user.name "Your Name"
git config user.email "you@example.com"
```

### SSH 鍵を接続する

対象環境で SSH 認証が既に使える場合は、その設定を利用できます。別の鍵を使う場合は **実行環境 → SSH 鍵の接続・管理（任意）** で既存の鍵を選び、**SSH 設定を保存** を押してください。鍵がなければ新しく生成することもできます。GitHub・GitLab に登録するのは **公開鍵だけ**です。秘密鍵は共有しないでください。パスフレーズ付きの鍵や社内 Git サーバーについては [SSH の詳細](docs/reference.ja.md#ssh-鍵を接続生成する)を参照してください。
