# Branchdesk

[English](README.md) · **한국어** · [日本語](README.ja.md)

**Windows와 WSL2의 Git 프로젝트를 한 앱에서 관리하세요.** 변경 파일 확인, 커밋, 브랜치 전환, 풀·푸시를 화면에서 처리할 수 있습니다. 한국어·영어·일본어를 지원합니다.

이 가이드는 앱을 처음 사용하는 개발자를 위한 안내입니다. [처음 실행](#1-처음-실행하기) → [프로젝트 열기](#2-작업할-프로젝트-열기) → [첫 커밋과 푸시](#3-파일을-수정하고-커밋푸시하기) 순서로 따라가면 됩니다. 세부 옵션과 소스 빌드는 [상세 참고 문서](docs/reference.ko.md)에 있습니다.

## 1. 처음 실행하기

1. [Branchdesk.exe 다운로드](https://github.com/antam2010/branchdesk/raw/refs/heads/main/Branchdesk.exe)를 눌러 원하는 폴더에 저장합니다. 이미 이 저장소를 클론했다면 그 폴더의 `Branchdesk.exe`를 사용하세요.
2. Windows 11 x64에서 `Branchdesk.exe`를 더블클릭합니다.
3. 시작 안내가 나오면 사용할 Git·Python을 연결합니다. Windows만으로 사용할 수 있으며, WSL을 쓰고 있다면 기존 WSL 환경도 사용할 수 있습니다.
4. 오른쪽 위 언어 선택에서 **한국어**를 선택합니다. 다음 실행에서도 기억합니다.

앱에는 Git과 Python이 필요합니다(Git 2.28 이상, Python 3.9 이상). 이미 설치되어 있으면 해당 실행 파일을 연결하고, 없다면 시작 안내의 **앱 전용 폴더에 설치**를 사용하세요. 화면을 여는 데는 Windows의 Microsoft Edge가 필요합니다. EXE로 사용하는 경우 소스 빌드나 Python 패키지 설치는 필요하지 않습니다.

## 2. 작업할 프로젝트 열기

여기서 여는 폴더는 **개발할 프로젝트의 Git 저장소**입니다. Branchdesk 앱이 들어 있는 폴더와 구분해주세요.

### 내 PC에 프로젝트가 있는 경우

1. **저장소 열기 → 기존 저장소 열기**를 선택합니다.
2. **이 저장소에서 사용할 환경**을 고르고 프로젝트 폴더 경로를 입력합니다.
3. 확인하면 저장소 탭과 커밋 히스토리가 열립니다.

실행 환경은 **이 프로젝트의 Git을 어디서 실행할지** 정하는 설정입니다.

| 프로젝트가 있는 곳 | 선택할 환경 | 입력할 경로 예시 |
| --- | --- | --- |
| Windows 폴더 | Windows | `C:\projects\my-app` |
| WSL Ubuntu 등의 Linux 폴더 | WSL2의 해당 배포판 | `/home/user/projects/my-app` 또는 `~/projects/my-app` |

원하는 환경이 목록에 없으면 **＋ 실행 환경 추가**에서 Windows 또는 WSL2를 선택하고 **이 환경 연결하기**를 누르세요. Git·Python을 자동으로 찾습니다. 찾지 못했을 때만 **프로그램 경로 직접 지정 (선택)**을 펼쳐 입력하면 됩니다.

Windows 프로젝트와 WSL 프로젝트를 각각 다른 탭으로 함께 열 수 있습니다. WSL 프로젝트는 해당 WSL의 Git으로 처리하므로 WSL 환경과 `/home/...` 경로를 연결해주세요.

### GitHub·GitLab에만 프로젝트가 있는 경우

1. 서비스에서 프로젝트의 Git 클론 주소를 복사합니다(예: `https://github.com/your-account/my-app.git`).
2. **저장소 열기 → 원격 저장소 클론**을 선택합니다.
3. 원격 주소, 사용할 환경, **새로 만들 로컬 폴더 경로**를 입력하고 실행합니다.

클론은 원격 프로젝트를 내 PC에 처음 내려받는 작업입니다. 이미 내려받은 프로젝트는 **기존 저장소 열기**를 쓰세요. 새 프로젝트를 처음 시작한다면 **빈 저장소 만들기**를 선택할 수 있습니다.

## 3. 파일을 수정하고 커밋·푸시하기

예를 들어 `feature/login` 브랜치에서 로그인 화면을 수정했다면 다음 순서로 저장합니다.

1. VS Code나 IntelliJ 같은 편집기에서 프로젝트 파일을 수정하고 저장합니다.
2. Branchdesk에서 **새로고침**을 누른 뒤 왼쪽 **파일 상태**를 엽니다.
3. 변경 파일을 클릭해 무엇이 달라졌는지 확인합니다. 새 텍스트 파일은 전체 내용을 보여줍니다.
4. 이번 커밋에 넣을 파일 옆 **＋**를 눌러 스테이징합니다. 잘못 골랐다면 **−**로 해제합니다.
5. 아래에 `로그인 화면 입력 검증 추가`처럼 변경 이유를 적고 **커밋**을 누릅니다.
6. 팀과 공유하려면 **푸시**에서 원격(보통 `origin`)과 보낼 브랜치를 확인하고 실행합니다.

**커밋은 내 PC에 작업 이력을 저장하고, 푸시는 그 커밋을 GitHub·GitLab 등에 올립니다.** 스테이징은 이번 커밋에 넣을 변경을 고르는 단계입니다. 다른 변경은 다음 커밋에 넣을 수 있도록 남아 있습니다.

팀에 코드 리뷰를 요청하려면 **원격**으로 저장소 웹페이지를 열고 Git 서비스에서 PR/MR을 만드세요.

커밋 버튼이 비활성화되어 있으면 스테이징한 변경과 커밋 메시지가 있는지 확인하세요. 사용자 이름·이메일 오류가 나면 [문제 해결](#문제가-생겼을-때)을 참고하세요.

## 4. 팀의 최신 변경 가져오기

작업 전 현재 브랜치를 확인하고 **풀**로 최신 변경을 가져옵니다. 아직 저장하지 않은 작업이 있으면 먼저 커밋하거나 **스태시**에 임시 보관하세요.

| 버튼 | 하는 일 | 사용할 때 |
| --- | --- | --- |
| 페치 | 원격의 최신 커밋·브랜치 정보를 가져옵니다. 현재 작업 파일은 바꾸지 않습니다. | 팀의 변경을 먼저 살펴볼 때 |
| 풀 | 원격 변경을 현재 로컬 브랜치에 반영합니다. | 내 프로젝트를 최신 상태로 맞출 때 |
| 푸시 | 로컬 커밋을 선택한 원격 브랜치로 올립니다. | 완료한 작업을 팀과 공유할 때 |
| 원격 | 연결된 저장소의 웹페이지를 엽니다. | GitHub·GitLab에서 PR/MR 등을 볼 때 |
| 원격 설정 | 연결 주소를 확인하거나 추가·수정합니다. | `origin` 등의 연결을 관리할 때 |

풀은 기본적으로 이력이 갈라지지 않은 경우에만 진행합니다(**Fast-forward만 허용**). 멈췄다고 기존 작업이 삭제되는 것은 아닙니다. 병합·리베이스가 필요하면 팀의 브랜치 운영 방식에 맞춰 선택하세요.

## 5. 브랜치 확인·전환·만들기

왼쪽 브랜치 목록에서 **한 번 클릭하면 그 브랜치의 커밋 위치를 보여주고, 더블클릭하면 전환 확인창이 열립니다.** 한 번 클릭하는 것만으로 작업 브랜치가 바뀌지는 않습니다.

브랜치를 옮길 때는 확인창의 대상 이름을 확인하고 진행하세요. **청소 (수정·스테이징·새 파일 변경 버리기)**는 기본 해제되어 있습니다. 이 옵션을 켜면 표시된 미커밋 변경을 버리므로, 작업을 보관하려면 해제한 상태로 사용하세요.

새 작업 브랜치는 **브랜치 → 브랜치 만들기**에서 이름(예: `feature/login`)과 시작점을 정해 만듭니다. **생성 후 체크아웃**을 선택하면 만든 브랜치로 바로 이동합니다. 원격에만 있는 브랜치는 **원격 브랜치 추적**으로 로컬 작업 브랜치를 만들 수 있습니다.

브랜치 병합, 충돌 해결, 커밋 되돌리기, 태그와 Git Flow는 [상세 기능 설명](docs/reference.ko.md#주요-작업)을 참고하세요.

## 6. 홈과 저장된 프로젝트 사용하기

- 왼쪽 위 **홈**을 누르면 최근에 열었던 프로젝트의 이름과 경로를 볼 수 있습니다. 클릭하면 다시 열거나 이미 열린 탭으로 돌아갑니다.
- 홈에 가도 열린 탭과 작성 중인 커밋 메시지는 유지됩니다.
- 탭의 **×**는 탭만 닫습니다. 최근 목록에서 다시 열 수 있습니다.
- **목록에서 제거**는 탭과 최근 기록을 정리합니다. 실제 프로젝트 폴더는 삭제하지 않습니다. 이미 삭제·이동된 경로도 제거할 수 있습니다.

**히스토리**에서 커밋을 클릭하면 해당 변경을 볼 수 있고, 파일을 더블클릭하면 미리보기를 크게 볼 수 있습니다. 커밋·파일·브랜치·탭을 우클릭하면 해당 대상의 메뉴가 열립니다. **터미널·탐색기**는 현재 프로젝트 폴더를 열 때 사용하세요.

## 7. 앱 업데이트하기

오른쪽 위 **앱 업데이트 → 새 버전 받기 → 적용 후 재시작**을 사용합니다. 다운로드 중에는 작업을 계속할 수 있고, 적용할 때 앱이 재시작됩니다. 열린 저장소와 커밋 메시지 초안을 복원합니다.

**앱 업데이트와 프로젝트의 풀은 별개입니다.** 앱 업데이트는 Branchdesk 실행 파일을 갱신합니다. 개발 중인 프로젝트에 `git pull`을 실행하지 않으며, Branchdesk 소스·README도 별도로 `git pull`해야 갱신됩니다.

## 문제가 생겼을 때

| 상황 | 확인할 내용 |
| --- | --- |
| Git·Python을 찾지 못함 | **실행 환경**에서 해당 환경을 확인하세요. 자동 검색이 안 되면 실행 파일 경로를 지정하거나 **필요한 프로그램 설치**를 사용하세요. |
| 클론·페치·풀·푸시 인증 실패 | 프로젝트에 선택한 Windows/WSL 환경의 인증을 사용합니다. SSH는 아래 안내를, HTTPS는 해당 Git 서비스의 인증 설정을 확인하세요. |
| 커밋할 때 사용자 이름·이메일 오류 | 해당 환경의 **터미널**에서 아래 Git 사용자 정보를 설정하세요. |
| 풀이 거절되거나 충돌함 | 로컬 변경을 커밋·스태시한 뒤 다시 확인하세요. 양쪽에 별도 커밋이 있으면 팀 기준에 따라 병합·리베이스가 필요합니다. 충돌 해결은 상세 문서를 참고하세요. |
| 풀·푸시·원격 버튼이 비활성화됨 | **원격 설정**에서 연결 주소를 확인하세요. 빈 저장소라면 첫 커밋을 만든 뒤 작업을 공유하세요. |
| 프로젝트 폴더를 지워서 열 수 없음 | 오류 화면이나 최근 목록의 **목록에서 제거**로 경로를 정리하세요. |
| 터미널·탐색기가 바로 보이지 않음 | 앱의 실행 결과 안내와 Windows 작업 표시줄에서 열린 창을 확인하세요. |
| 업데이트에서 `Replace`·경로 형식 오류가 나옴 | 구버전 도우미의 오류입니다. 앱을 닫고 **Branchdesk 저장소 폴더에서** `git pull`한 뒤 그 폴더의 새 `Branchdesk.exe`를 한 번 실행하세요. |
| `git pull`이 README 등의 로컬 변경 때문에 중단됨 | 로컬 편집을 먼저 커밋하거나 스태시에 보관한 뒤 풀하세요. 편집을 지우거나 강제 초기화할 필요는 없습니다. |

커밋 사용자 정보를 **현재 프로젝트에만** 설정하는 예시입니다. 이름과 이메일을 본인 정보로 바꿔 입력하세요.

```bash
git config user.name "Your Name"
git config user.email "you@example.com"
```

### SSH 주소로 연결하려면

이미 해당 환경에서 SSH 인증이 된다면 기존 설정을 그대로 사용할 수 있습니다. 다른 키를 연결하려면 **실행 환경 → SSH 키 연결 · 관리 (선택)**에서 기존 키를 고르고 **SSH 설정 저장**을 누르세요. 사용할 키가 없다면 새 키 생성도 가능합니다. **공개키만** GitHub·GitLab 계정에 등록하며, 개인키는 공유하지 않습니다. 암호가 있는 키와 사내 Git 서버 설정은 [SSH 상세 안내](docs/reference.ko.md#ssh-키-연결과-생성)를 참고하세요.

## 더 자세히 알아보기

[상세 참고 문서](docs/reference.ko.md)에서 프로그램 경로·SSH·기능별 옵션·소스 실행·EXE 빌드·테스트 방법을 확인할 수 있습니다. 앱을 그냥 사용하는 경우 빌드나 테스트 과정은 진행하지 않아도 됩니다.
